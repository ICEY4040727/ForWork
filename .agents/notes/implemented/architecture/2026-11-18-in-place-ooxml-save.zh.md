# Agent Note: In-place OOXML save preserves source package bytes

Status: implemented

[English](2026-11-18-in-place-ooxml-save.md) | 中文

## 问题

从可编辑模型重建 Office 包会丢失或拒绝模型未表示的每个构造。真实的 `.docx` 或 `.xlsx` 通常带有图表、自定义主题、数据透视表、另一条款中的修订或 VBA 项目；重新生成往返会丢弃这些部件，而旧行为只要文件任意位置存在这些内容就拒绝保存。用户可见的代价要么是静默丢失，要么是文档无法保存。保留必须从用户打开的文件出发，而不是从编辑器能够序列化的内容出发。

## 决策

`@forwork/office-exchange` 通过两层写入。Host-only 的 ZIP/OPC 层索引源包，从源本地记录复制每个未改动条目，并重建中央目录；XML 区间层只在发生改变的部件内替换被编辑单元。无操作保存返回源字节。`.docm` 与 `.xlsm` 在相同规则下可编辑，因此 VBA 项目与宏启用的主内容类型得以保留。没有源包的快照仍使用重新生成写入器。

[规格](../../../../specs/002-in-place-ooxml-save/spec.md)、[计划](../../../../specs/002-in-place-ooxml-save/plan.md)、[写入契约](../../../../specs/002-in-place-ooxml-save/contracts/office-exchange-write.contract.md)与[数据模型](../../../../specs/002-in-place-ooxml-save/data-model.md)拥有完整的验收标准与实体定义。[包 README](../../../../packages/document/office-exchange/README.zh.md) 拥有消费方契约。

### 为什么直接复制 ZIP 本地记录

已安装的 ZIP 库都无法原样传递压缩条目。`fflate.unzipSync` 只返回解压后的 payload，`zipSync` 会重算 CRC、重新压缩、排序条目、写入固定 mtime，且无法复现归档注释。`yauzl` 暴露压缩字节但没有写入器，`jszip`、`archiver` 与 `unzipper` 都会重建或解包。因此，即使没有任何编辑，重建归档的无操作保存也会在字节同一性要求上失败。

包写入器逐字节复制每个未改动的 `localRecord`，包括其压缩方法、压缩数据、CRC、时间戳、扩展字段与可选数据描述符。它只修补被携带的中央目录记录的偏移字段，并用原始归档注释写入中央目录结束记录。被改动的条目通过 `node:zlib` 的 `crc32` 与 `deflateRawSync` 重新编码，存储条目仍保持存储。这样改动被限制在被编辑条目内，依赖数量保持为零；[R1](../../../../specs/002-in-place-ooxml-save/research.md) 记录了库选型调查。

### 为什么使用自定义字节扫描器

扫描器必须报告原始 UTF-8 部件中的偏移，因为在解析器规范化后的偏移处拼接会破坏文件。`fast-xml-parser` 5.11.1 有 `captureMetaData`，但它在记录 `startIndex` 与 `endIndex` 之前把 `\r\n` 与 `\r` 规范化为 `\n`，因此第一个 CRLF 之后的每个偏移对源字节都是错误的。`fast-xml-validator` 只暴露行与列，并在扫描前剥离 BOM 与声明。现有正则目录不感知引号、注释与 CDATA，并假设字面 `w:` 前缀。

`src/source/xml-spans.ts` 单次扫描部件，解析命名空间 URI，跟踪引号、注释、CDATA、处理指令与 DOCTYPE，并处理自闭合标签与 `>` 之前的空白。它保留 CRLF 与 BOM，并在区间含义不明时失败关闭，而不是猜测偏移。解析器仍作为仅 LF 夹具上的测试判据；它不能成为生产真源，如 [R3](../../../../specs/002-in-place-ooxml-save/research.md) 所述。

### 为什么锚点位于 `data.officeExchange.source`

快照必须把源身份与逐单元锚点带过 `unit.save()`、JSON 线缆、编辑器往返与恢复草稿；其中任何一步丢弃或改写这些数据，都会使后续保存找不到区间。`OfficeDocumentSnapshot` 包装层是具有声明形状的对象，其未知字段会被编解码器剥离；`resources` 在保存时被替换；`body.payloads` 已记录为不写入磁盘。段落没有可用的持久槽位，单元格的 `custom` 字段会被自动填充删除，并被复制/粘贴复制。

位于可编辑 `data` 对象内部的提供方自有纯 JSON 命名空间能通过全部四条路径。它保存 schema 版本、打开时的格式、源摘要与字节长度、锚点模式、源部件，以及 `UnitAnchor` 条目或逐工作表摘要之一。每个锚点携带模型 key、字节区间与规范单元摘要，因此保存时的变更检测比较身份与内容，而不是位置索引。[R5](../../../../specs/002-in-place-ooxml-save/research.md) 记录了传输方案的其他选择。

### 耦合与独立构造

源文件存在未建模构造并不构成拒绝。写入器对被编辑的源区间分类。含义不引用被改文字或节点身份的属性是独立的，会合并进重新生成的单元：单元格的 `s` 样式索引、`w:tcPr` 与 `w:trPr` 子元素、未映射的 `w:pPr` 与 `w:rPr` 子元素、单元格宽度与适应文字。含义或锚点依赖被改内容的构造是耦合的，保存会拒绝并指出该构造：覆盖该单元的修订或批注区间、包裹被编辑文字的内容控件、结果即该文字的域、富文本共享字符串、共享或数组公式、目标位于关系部件中的改动工作表超链接，以及含义不明的 `mc:AlternateContent` 分支。

分类来自源区间，而不是文件级的不支持列表，因此另一段落中的图表绝不会阻止文字编辑，而围绕被编辑句子的修订会阻止。[R12](../../../../specs/002-in-place-ooxml-save/research.md) 拥有该拒绝规则。

### 保存时重新锚定

成功的保存会重写文件，因此快照中读取时的偏移与摘要不再描述磁盘上的字节。编辑器不重新读取就采用已发布的版本，从而保留实时单元与其撤销历史。因此第二次保存会提供新的源字节，以及按旧字节记录的 sidecar。

写入器把 sidecar 的 `packageDigest` 与 `byteLength` 与提供的源比较。不一致时，它会在规划拼接前从该源重建锚点，然后以相同的模型 key 比较当前模型与那些锚点。无法重新锚定的源以 `conversion-failed` 拒绝。文件系统的 `replaceIfVersion` 守卫仍是并发外部变化的最终权威，因此过期的源是冲突，而不是重新锚定。

## 考虑过的替代方案

**整包重建并为未建模部件保留原始块。** 重新生成写入器已经以不透明方式携带部分部件，但它仍重建每个条目、重新排序或重新压缩归档，并丢失模型未命名的任何部件。它无法满足无操作保存的字节同一性或区间级同一性，而本决策正是要替换该行为。

**通过已安装的 ZIP 库写入。** `fflate` 无法复用压缩流、保留本地与中央元数据或写入归档注释；其他已安装库会解包或重新压缩。为一个仍会重新压缩的写入器新增依赖无法保留字节，如 [R1](../../../../specs/002-in-place-ooxml-save/research.md) 所述。

**使用 `fast-xml-parser` 的 `captureMetaData` 获取区间偏移。** 它的 CRLF 规范化使第一个 CRLF 之后的每个偏移都错误。把它保留为仅 LF 夹具上的测试判据，能保留其价值而不让它成为权威。

**把锚点放在快照包装层、`resources` 或逐单元字段中。** 包装层剥离未知字段，`resources` 会被替换，`body.payloads` 不会持久化，段落没有自定义槽位，单元格 `custom` 在复制/粘贴或自动填充后也不稳定。

**拒绝被编辑单元内的每个未映射属性。** 这会让拒绝集合保持很大，并拒绝普通文件，因为被编辑段落带有模型未命名的属性。合并独立属性、只拒绝耦合构造是更小的剩余集合；全部拒绝是更简单的替代方案，但会失去该功能对用户可见的收益。

**总是携带被编辑区间内的每个构造。** 被携带的修订或共享公式可能指向编辑已删除的内容，产生无效或语义错误的文档。这些构造是耦合的，必须拒绝。

**每次保存后强制重新读取，而不是重新锚定。** 重新读取会丢弃实时单元与其撤销历史，并迫使编辑器重建写入器在现有版本守卫下已经能与新源比较的内容。

## 结果

该包新增 Host-only 的 ZIP/OPC 层与源区间层，各自拥有测试与失败模式；`node:zlib` 仍是唯一新增的运行时原语。无操作保存与每个未改动条目保持逐字节一致，并且文档化语料中的文件可以打开而不触发修复。没有源 sidecar 的快照（包括旧草稿）保留先前的重新生成行为，因此该包的契约现在有两条具有不同保留保证的写入路径。

辅助部件仅追加：必需的样式或编号定义被添加而不重新生成部件；被编辑的工作表单元格样式会复用匹配的 `<xf>`，或只向 `xl/styles.xml` 追加所需的数字格式、字体、填充、边框与 `<xf>` 条目，并更新该集合的计数。Word 表格几何变化或单元重排会被拒绝，因为无法表示为区间操作；写入器无法表达的工作表样式组件也会拒绝并指出该组件。保存处置是持久的但仅供审计；`document` 投影不暴露它。[夹具语料](../../../../packages/document/office-exchange/tests/fixtures/README.zh.md)与 [LibreOffice 加载冒烟](../../../../packages/document/office-exchange/tests/ooxml-engine.spec.ts)是证据基础，字节比较工具会把每份报告的处置与实际输出核对一致。
